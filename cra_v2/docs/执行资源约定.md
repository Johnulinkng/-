# 当前训练资源约定

更新：2026-09-16。用户最新明确授权：后续训练优先利用空闲GPU，处理时根据实时资源灵活决定，可以使用时直接执行，不需要重复确认。

- 新批次启动前核对实际GPU利用率、空闲显存、计算进程及Windows/WSL可用RAM；不根据旧截图或单次平均利用率推断可用容量。不终止其他项目进程。
- 同一配对实验的神经控制与候选使用相同训练设备；设备、GPU身份、显存比例、确定性/TF32设置和源验证设备纳入冻结计划。批次中途改变设备需另行登记，不能悄悄混合CPU/GPU结果。
- GPU训练模型在同一训练设备重放源验证，保留原选模轮次和误差检查。CPU推理一致性另测，不因设备舍入差异重选模型或放松已冻结CPU实验规则。
- 优先使用满足模型实际需要的显存上限；PyTorch显存比例限制只约束该进程分配器，不是全局预留，也不覆盖全部驱动/上下文开销。每模型启动边界重新检查共享资源。
- 不创建五分钟监控或自动等待队列，训练期间不开展依赖最终结果的旁支实验。资源不足时在可验证边界停下，恢复时先核对已有实例和工件，避免重复启动。

当前已验证GPU：RTX 3070 Ti Laptop GPU，8 GiB。`audit/actual_wdgrl_cuda_smoke_20260916/result.json`：8个合成CUDA模型（3→3及每个目标单槽、非对抗/WDGRL）通过，PyTorch峰值分配65.39 MiB，不代表整个进程的总显存需求。`audit/gpu_fit_replay_20260916/result.json`：两个60轮合成CUDA模型通过正式训练工件/同设备源验证入口。均未读取真实目标数据或产生实验性能结论。

根训练器已支持显式CUDA基础CE/均值融合，GPU运行名独立后缀；旧CPU默认路径保留。GPU计划/验证检查22项mock测试通过，24项CPU/解析回归通过。后续具体实验仍需冻结对应GPU资源门禁与计划；不能直接使用旧清空CUDA设备的CPU启动脚本。
