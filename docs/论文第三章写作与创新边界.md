# 论文第三章写作与创新边界

## 推荐章节定位

建议题目：**面向通道缺失与工况偏移的严格无标签机械故障迁移诊断方法与系统评估**。

这一章可以形成完整工作量：统一问题定义、模型改造、严格训练协议、强基线、四类任务矩阵、噪声实验、消融式因果比较和负迁移机制诊断都已经落地。当前数据不支持把标题或摘要写成“提出一个在所有任务上高性能的新 WIDAN”。更准确的主张是：建立一套可处理 3→3 与 3→1 的统一结构和反泄漏评估协议，并定量揭示无条件边际对齐在通道数与工况同时变化时的失效边界。

## 可写的三项贡献

1. **统一变通道建模。** 将原 WIDAN 的经验双分支改为共享逐通道编码器、均值锚定的可学习融合和非空随机通道屏蔽。同一结构处理三通道目标和单通道目标；三个目标单槽使用相同代码但独立训练权重。
2. **严格且可归因的 UDA 协议。** 目标训练标签始终屏蔽；共同 source-only 锚点后，控制与候选复制模型、优化器、调度器和随机状态，再固定训练 20 轮。全部 checkpoint 先封存，再统一读取 target-dev。该设计区分“训练机会差异”与“域对齐本身”的效果。
3. **负迁移保护与失效诊断。** CRA-v2A 使用物理槽平衡的 equal-B fixed-kernel U-statistic MK-MMD，并在源分类梯度与对齐梯度冲突时关闭对齐更新。冻结筛查证明该保护仍不能保证目标类别语义：94.18% batch 关闭对齐后，双跨仍退化并出现类别错配。这个结果支持把类条件错配、聚合宽度不一致和优化器累计剂量作为下一阶段明确问题，而不是继续堆叠论文模块。

这些贡献是问题定义、结构改造、估计合同、配对协议与系统证据的组合。MMD、通道 dropout、attention、PCGrad 类冲突处理各自已有先例，不能单独声称首次提出。

## 结果应怎样写

- 强基线开发矩阵：源验证选参线性 Ridge 的 clean Acc/Macro-F1，水泵为 68.400/67.003%，实验室齿轮箱为 76.500/75.818%，SEU 为 63.917/62.465%。
- 跨工况/双跨 3→1：线性 Ridge clean 均值，水泵 57.622/56.918%，实验室齿轮箱 73.500/72.345%，SEU 32.861/31.592%；逐槽结果必须同时报告。
- CRA-v2A 因果筛查：7/16 配对双指标提高，平均 Accuracy/Macro-F1 为 −0.34/−0.37 pp，双跨 F1 为 −1.98 pp，性能门失败。
- 噪声：20/10/0 dB 均已评估；0 dB 明显退化，只能称具有受控中等噪声可用性，不能称强噪声鲁棒。
- 固定模型 final：线性 Ridge 59.675/58.338%，RBF-KRR 55.893/53.666%，必须注明 post-exposure fixed-model estimate。

## 不能写的结论

- 不能按目标开发分数为不同任务挑不同模型，再汇总成统一方法成绩。
- 不能把单个 seed、最好槽、最好 epoch或源域 100% 准确率写成稳定提升。
- 不能把 AWGN 的三个噪声实例当作训练多种子或独立采集重复。
- 不能把一条长记录切出的随机窗口写成跨设备或跨独立采集泛化。
- 不能把 CRA-v2A 的完整性审计 PASS 写成性能门 PASS。

## 下一篇正向方法论文的最小条件

若继续追求统一正向新模型，应先完成源侧伪目标机制预检，再冻结一个单因素候选；代理门不过就停止目标梯度路线。候选通过后才补 3–5 个训练种子、外部 SEU 全矩阵、新的未暴露确认集以及噪声复核。当前交付已经保留该路线的诊断和预注册依据，但没有把未运行的 v2B 写成已完成成果。
